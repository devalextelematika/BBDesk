---
name: dashboard
description: Use the BBDesk plugin's launcher and selected-project activity screen.
---

Open BBDesk through BB navigation. Add applications through Catalog; the main button opens here, the split button opens alongside or in a new tab if BB cannot split. Project selection and launcher order belong to this plugin, not the BB sidebar. The stable plugin id remains `dashboard` and its page is `/plugins/dashboard/home`.

Thread split mode uses a single row of resizable native chats. Drag a bottom tab (including More) or a history entry onto the left/right half of a chat, or use Alt+Enter on a tab / Open alongside in history. Existing columns stay mounted. Clicking a column activates it; ordinary tab selection replaces that column or focuses an existing one. Header X removes a column without hiding/archiving/stopping its thread. History entries remain temporary bottom tabs while open. Dividers support pointer dragging, arrow keys (Shift for larger steps) and double-click equalization. Minimum column width is 320px; excess columns scroll horizontally. Layout, active column and widths persist in this browser's localStorage per project.

Catalog includes a Shared pool checkbox, separate from the project list. While it is off, the pool button and its view stay hidden; pinned threads remain saved in this browser. The Shared pool button sits at the right of the project row, beside project selection, and stays put when project tabs scroll. It shows the same provider marks on the left and thread status indicators on the right as a project tab, in stable thread-id order. Drag a bottom tab, a More entry, or a previous-thread row onto it, or use the pin on those rows. Pinning adds or removes membership and leaves the current project open. Activating the button shows the pinned threads as split columns; each column names its project above the native chat. Removing a column edits pool membership only and does not hide, archive, or stop the thread. Choosing a project tab restores that project's own split. Membership, the open view, the active column and widths persist in this browser separately from per-project splits. Archived threads, threads hidden in BB, and subagents are left out; a thread hidden only from a project's working set can still be pinned from previous threads. A thread whose project is disabled stays in the pool, labeled unavailable, until it is removed. The new-thread button beside the pool and in its thread row opens a composer and pins the created thread into the pool. Dragging a bottom pool thread before or after another changes their order; the split columns follow that order and keep their widths and the active column. Header indicators still select the thread's project and open that thread.

The interface defaults to English. Change Interface language to English or Русский in BBDesk's installed-plugin settings in BB. The choice is server-wide and persists across reloads; there is no automatic browser-language selection. User content and native BB controls keep their own language.

Shared pool capacity is 50 entries, including unavailable saved conversations. A full pool rejects submission before spawning and keeps the native draft. Capacity is checked again when a pending spawn completes. If it filled meanwhile, or the result was explicitly unpinned, the created conversation remains available through Open in the current workspace. This recovery control is transient and is not persisted across reloads; the thread remains in BB. Late results may pin when possible but preserve newer navigation. Turning the pool off cancels its composer; results cannot reopen it even after it is enabled again. Disconnecting the composing project restores an available selection and prevents its late result from navigating back.

Catalog lists BB projects and application screens, with Common threads (the main stream outside projects) as a special control in My lists. Common threads is a separate row with its own checkbox color and connects through that checkbox the same way as a project. Connecting a project imports current work, queued work and pending interactions, not old completed answers. Subsequent results stay until manually hidden. Hiding never archives, deletes or stops a thread. Fresh activity returns hidden threads. Chat, drafts, attachments, execution and permissions are owned by BB.

BBDesk remembers the last selected independent conversation per project, including historical conversations, within the current browser-tab session and through reloads. Missing/archived/hidden selections fall back to activity priority. Thread search and the All threads/attention selector are removed. Use bottom tabs, recent history and the full project screen to navigate conversations.

Activity snapshots contain the last confirmed state and schedule SDK refresh separately. `syncedAt` may be null before the first complete full pass. Configuration RPCs confirm saved settings without waiting for activity import; a later `syncError` reports synchronization failure and does not undo those settings. Cached snapshots and targeted updates do not advance the full-pass timestamp or clear a synchronization error. The service refreshes periodically and after relevant events; do not treat a cached snapshot as proof of a fresh SDK scan.

The existing six RPC methods, whole-list replacement operations and storage formats remain supported. Catalog rename/restore and thread restore are compatibility paths even though Catalog no longer presents those controls. See [RPC compatibility](../../docs/RPC_COMPATIBILITY.md) and [workspace transitions](../../docs/WORKSPACE_TRANSITIONS.md). The frontend separates snapshot refresh, pure selectors/transitions, asynchronous actions and project/pool views; chat execution, drafts and permissions continue to use native BB components. Source/harness checks do not establish acceptance in an installed BB host or across every version in the declared SDK range.

Recent history shows up to two lines of title, activity date and environment, and a link to BB's full project screen. At workspace widths up to 680px it overlays the chat and closes on selection; projects stay on one scrolling row and the heading is compact. On wider workspaces history remains a right column. Settings/pickers close on Escape and return focus to the opener. Hidden tabs disappear as soon as hiding succeeds, with no timed placeholder or tab Undo. Hiding a background tab keeps the current conversation open; hiding the selected tab selects a neighbor.

Existing chats expose BB's editable permission picker. After a successful submission, BB owns that thread's execution defaults; BBDesk also remembers the submitted permission mode locally in this browser for new BBDesk threads across projects and reloads. Opening an older thread or changing an unsent draft does not replace this preference. Existing threads keep their own modes. BB reconciles the new-thread seed against provider capabilities and machine limits.

Delegated subagents appear only as indicators in the header and their project tab, without thread rows or automatic chat expansion. Clicking an indicator can open the subagent chat. When its work completes, its indicators disappear and an open subagent chat returns to its manager, or closes if the manager is unavailable. Pending interactions, queued work and errors remain visible through indicators. Completed subagent results do not persist on the dashboard; their BB history is preserved. Independent forks retain ordinary thread behavior.

Catalog has Projects and Applications tabs, each with one compact searchable list. Green checked rows are connected. Toggle the checkbox or label to connect or disconnect immediately without opening an entry or closing settings. Reorder directly in the project bar and launcher. Settings have no duplicate selected lists, reorder, rename, open or Undo controls. Done closes without a Save step. Common threads and Shared pool remain checkboxes in Projects. Unavailable saved entries can be disconnected from the same list. One small settings icon on the right of the top toolbar opens Catalog; the native chat and draft remain mounted.

The BBDesk navigation provider wraps BB's original rail and shares its live navigation model with the launcher. Automatic navigation selects it when no other third-party navigation provider takes precedence. If another provider is pinned, choose BBDesk under Settings → Appearance → Navigation to connect launcher destinations and native current/split actions. The thread-list provider, native navigation order and visibility settings are independent and remain in effect. Hidden navigation screens are still available to add to the launcher.

The center of the top bar shows one continuous line of thread indicators from all selected projects, without visible labels or project groups. Each indicator identifies its project, title and status through a tooltip and accessible label; click it to select that project and open that exact thread. Order is stable across status changes, and indicators wrap when space is limited. Project tabs show one quiet provider icon per distinct agent provider among that project's open threads, to the left of the project name. The same threads repeat their status indicators beside the name. Tabs remain available for navigation and new-thread creation. Their indicators use the same states and stable order as the top bar, with thread titles and statuses in tooltips. A provider icon's tooltip names that provider and the open threads that use it.

The top-bar menu button hides/reveals the application panel. Drag its right edge to resize, or focus the separator and use Left/Right (Shift for larger steps), Home or End. Below 680px of dashboard width it overlays the workspace; click outside or press Escape to close. Open state and preferred width persist locally in each browser, separately from the shared project/launcher settings. Resizing the BB pane temporarily constrains the panel without changing its saved preferred width. Opening launcher settings in a narrow pane closes the drawer so the settings remain accessible.
